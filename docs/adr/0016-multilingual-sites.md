# ADR 0016: 多言語サイトはロケール定義・文言カタログ・ロケール別書式の 3 つで作る

- ステータス: 採用（2026-09-12）

## 背景
japan-open-today は日本語・英語・繁体字で出す。一次情報は日本語で、事実（時間・料金）は原文から機械抽出したものしかない。
文章をまるごと翻訳すると、事実が原文からずれたまま複数言語に広がる。エンジンとしては「事実は構造化データから
言語ごとに描画する」やり方だけを支える。akiya-atlas（単一言語）に影響を出さないよう、すべて追加だけで作る。

## 決定

### ロケール定義
- `site.toml` の `[[locales]]` に `code` / `path` / `label` / `html_lang` / `og_locale` / `default` を書く
- 書かなければ `language` の 1 ロケールとして扱う（単一言語のサービスは何も変えなくてよい）
- **既定ロケールの `path` は空**にする（ルートに置く）。hreflang の `x-default` が指す先が決まらないため
- `language` は `[[locales]]` のどれかに一致していなければならない

### ページとロケール
- `PageMeta.locale` にロケールコード、`PageMeta.alternates` に `{ロケール: url_path}` を持つ。**自分自身も含める**
- ビルド前に `preflight.check_pages` が検査する:
  - 未知のロケールを指していないか
  - `alternates` が自分自身を正しく指しているか
  - 相手のページが存在し、**同じ対応を持っているか**（片側だけの hreflang は検索エンジンに無視されるため）
  - 多言語サイトで `alternates` が空のページ（noindex は除く）
- `head_meta` マクロが `hreflang`（＋ `x-default`）と `og:locale` を出す。テンプレートが渡し忘れたときは、
  ページ個別の検査（`expect_hreflang`）がビルドを止める
- sitemap にも各言語版を `xhtml:link` として書く

### 文言カタログ
- サービスの `i18n/<code>.yaml`。入れ子は `nav.today` のような平らなキーに畳む
- 入れるのは**画面の文言だけ**。施設名や説明文のようなデータは入れない（データはレコードとして持ち、出典を添える）
- 未翻訳のキーは既定ロケールの文言に落とし、**ビルドは止めずに実行レポートの警告**に出す
  （3 言語すべてが揃うまで公開できないのは運用として重すぎる）
- どのロケールにも無いキーは `TranslationError` で止める（テンプレートの書き間違い）
- Jinja からは `t('key', 数=...)`。マクロの中は描画中の context が見えないため `t_in(locale, 'key')` を使う

### ロケール別の書式
- `i18n/format.py` に「書式は data、コードは組み立てるだけ」で持つ（`LocaleFormat`）。ja / zh-Hant / en を同梱し、
  `register_format` でサービスが足せる。未知のロケールは言語部分 → 英語の順に落ちる
- **時刻は全ロケールで 24 時間表記**。原文が 24 時間表記で、12 時間表記への変換は
  「17:00 を 5:00 と書く」種類の取り違えを生む
- Jinja のフィルタ `date_l` / `date_short_l` / `datetime_l` / `time_l` / `weekday_l` / `number_l` / `money_l`
  （描画中のロケールを見る）と、ロケールを明示する `fmt_date` などのグローバル関数を用意する
- 既存の `date_ja` / `datetime_ja` / `yen` は挙動を変えずに残す

## 影響
- 単一言語のサービス（akiya-atlas）は `[[locales]]` を書かなければ出力が 1 バイトも変わらない
- ロケールを増やす作業は「カタログ 1 ファイル＋テンプレートの文言」に収まる
- 施設名のように「公式の表記があればそれを使う」ものはカタログではなくデータとして持つ（japan-open-today ADR 0005）
