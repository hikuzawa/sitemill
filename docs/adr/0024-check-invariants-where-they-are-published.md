# ADR 0024: 守りたい性質は、公開する直前に確かめる。コミットするものはキャッシュしない

- ステータス: 採用（2026-09-16）
- 関連: ADR 0012（公開前検査と個人情報）、ADR 0020（ライセンス済み画像の取り込み）
- 由来: japan-open-today ADR 0006 追記（2026-09-16）の実例

## 背景

japan-open-today で、12 の寺のページに善通寺の写真が出ていた（2026-09-13）。原因は Commons の
カテゴリページの読み方で、エンジンを直し（ADR 0020 追記）、取り込みの道具にも「他の場所が
使っている画像は採らない」歯止めを入れて、同じ日に直した。

**その夜の日次パイプラインで元に戻り、本番に 09-14 の朝から 09-16 まで誤った写真が出ていた。**

戻したのは取り込みではなかった。サービスの `pipeline.yml` の `actions/cache` が `data/assets` を
まるごと持っていて、その中にコミット対象の `assets.json` も入っていた。キャッシュの復元が
checkout したばかりのファイルを古い版で上書きし、データのコミット工程がそれをコミットした。
取り込み側の歯止めはこの経路を通らないので、何も言わなかった。

リポジトリを作り直したとき、キャッシュが空の配置ログ（102 件を取り直し、同じ画像を 12 回再判定）
を読んで気づいた。検査で見つけたのではない。

## 決定

### 1. 守りたい性質は、書き込む場所ではなく出す直前に確かめる

「1 枚の写真は 1 つの場所」「信頼シグナルがある」「登録済みでない `<img>` が無い」のような性質は、
データがどの経路で今の形になったかに関係なく、**公開する生成物（またはその直前のデータ）に対して**
確かめる。書き込む道具に入れた歯止めは、その道具を通ったものしか守らない。キャッシュの復元、
手での編集、`git` の取り込み、別の道具、将来の自動修正――経路は増える一方で、全部に歯止めを
置くことはできない。

- 取り込み側の歯止めは残してよい（早く気づける）。ただし**それを保証とみなさない**
- 保証は配置の直前の検査で持つ。ADR 0012 の公開前検査と同じ位置に置き、破れていたら配置を止める
- 同じ検査を、コミット済みのデータに対するテストにも当てる（push のたびに気づける）
- 「同じもの」の判定は、変わりうる id で行わない。japan-open-today ではバイト列のハッシュ
  （`asset_id`）ではなく、Commons の説明ページで数えた。サムネイルは再生成で id が変わる

### 2. コミットするものはキャッシュしない

CI のキャッシュは「無くても作り直せる、git 管理外のもの」だけに使う（生 HTML、LLM の応答、
画像の実体）。**コミット対象のファイルがキャッシュのパスに含まれていたら、除外する**
（`!path/**/assets.json` のような除外指定）。キャッシュの復元は checkout の後に走るので、
含まれていれば必ず上書きされる。

キャッシュの中身を変えたときは鍵の接頭辞も変える（`-v2-` など）。`restore-keys` の前方一致で、
古い中身のキャッシュが復元され続けるため。

### 3. 検査に通った実例を、失敗の経緯と一緒に残す

性質を足すときは「何が起きたか」「なぜ既存の歯止めで見えなかったか」を ADR に書く。
検査の条文だけを残すと、後から「取り込みで防いでいるので要らない」と外されやすい。

## サービスが確かめること

- `.github/workflows/` の `actions/cache` の `path` に、コミット対象（`data/records`、`data/state`、
  `data/assets/**/assets.json`、サービス固有のコミットするデータ）が含まれていないか
- 「一度直したのに戻った」ことがあるなら、戻した経路を特定する前に、公開直前の検査を足す

## 影響

- 公開前検査が少しずつ増える。1 つあたりは生成物かデータを数えるだけで、日次の所要時間には
  ほぼ影響しない（japan-open-today の写真の重複検査は 1 秒未満）
- キャッシュの鍵を変えた直後の 1 回は、キャッシュが空の実行になる（画像を取り直すぶん数分延びる）
