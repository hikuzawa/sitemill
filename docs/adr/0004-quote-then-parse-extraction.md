# ADR 0004: quote-then-parse。LLM は引用だけを返し、数値は決定的パーサが作る

- ステータス: 採用（2026-09-10）

## 背景
価格・面積・築年・締切などの数値に LLM の推定値が混ざると、誤った情報を公開するリスクがある。

## 決定
- LLM の出力スキーマでは、数値項目を `*_quote`（原文からの逐語引用）として受け取る。値そのものは受け取らない
- sitemill は各引用が正規化した本文中に実在するかを検証し、見つからなければ `quote_not_in_source` にする
- 引用は `parse/jp` の決定的パーサ（金額・面積・和暦・全角数字）で値にする。解析できなければ `unparsed`、引用が無ければ `not_found`
- 結果は `FieldValue{value, quote, status, note}` として値と根拠を一緒に保持し、ページには値と出典を並べて出せるようにする
- 「築40年」のような相対表現は基準日が要るため `unparsed`（note=relative_age）にし、推定しない
- 要約・タイトルなど自然文だけ LLM が生成する。要約は長さ上限を持ち、本文の 30 文字以上の逐語一致を含む場合は転載とみなして定型文に置き換える

## 影響
- 抽出率はパーサの守備範囲に依存する。`eval` コマンドで項目ごとの状態を集計し改善の入力にする（ADR 0010）
- プロンプトには「値を計算するな、原文の該当箇所をそのまま写せ」を明記する

## 追記（2026-09-12）: 表の行を繋いだ引用を、断片ごとに照合して認める

引用が本文に逐語で存在することを条件にしていたが、**表から値を取るときに必ず落ちる**ことが
分かった。本文では表のセルが改行で区切られているため、LLM は行を「、」で繋いで返す。

    本文:   03/21~10/20 ⏎ 8:30~17:00 ⏎ 10/21~11/30 ⏎ 8:00~17:00
    引用:   03/21~10/20 8:30~17:00、10/21~11/30 8:00~17:00

「、」は本文に無いので全体照合は落ちる。しかし値はすべて本文のものである。寒霞渓の営業時間は
この形の表しか無く、照合で落ちるかぎり永久に「不明」のままだった。

`verify_quote` は、全体が見つからないときに区切りで切った断片を照合し、**すべての断片が
逐語で見つかる**場合だけ実在と認め、`quote_joined` を注記に残す。断片が 1 つでも本文に
無ければ認めない（時刻や金額を作った引用はここで落ちる）。断片の最小長は 4 文字とし、
「,」と「/」は数字に挟まれた位置では切らない（2,340円・03/21 を壊さないため）。

この緩和で通らないものは、LLM が語や括弧を書き足して再構成した引用である。これは引用ではない
ので落としたままにする（寒霞渓の料金表は「A期間(3月21日~10月31日)」と括弧を足していたため
不採用のままになった）。
