# ADR 0020: ライセンス通過画像のパイプラインと、出典の付いた画像だけを出す検査

- ステータス: 採用（2026-09-12）

## 背景
ADR 0005（ホワイトリスト・既定不採用）と ADR 0008（視覚要素の三系統）で設計だけ決めて、`assets/` は
インターフェースのままだった。japan-open-today は観光サイトで、写真は最も権利の重い部分なので実装する。

## 決定

### 取得と保存
- `fetch_asset(url, verdict, policy, store, client=...)`。**判定はここでしない**。
  `license.detector` か `assets.commons` が済ませた `LicenseVerdict` を受け取り、
  `allowed` でなければネットワークに触る前に `AssetError` で拒む
- `AssetPolicy` が種類（image/jpeg・png・webp・svg）と大きさ（1KB〜5MB）とサービス固有の除外を見る
- 保存は `data/assets/<source_id>/<sha256 の先頭 16>.<ext>`。隣の `assets.json` に
  元 URL・説明ページ・ライセンス判定・取得日時・作者・クレジット文を残す。
  画像の実体はローカルキャッシュ（git 管理外）、`assets.json` はコミットしてよい

### Wikimedia Commons（`assets/commons.py`）
- **robots.txt の制約**（実測）: `commons.wikimedia.org` は `/w/` と `/wiki/Special:` が Disallow。
  つまり **API 検索も `Special:FilePath` も使えない**。許可されているのは `/wiki/File:`・`/wiki/Category:` と
  `upload.wikimedia.org`。したがって「カテゴリページ → ファイルページ → ライセンス欄」で辿る。
  カテゴリ名はサービス側のデータとして持つ（推測を engine に埋めない）
- **ライセンス欄の断片だけを判定にかける**。Commons は全ページの下部にサイト自身の規約（CC BY-SA）への
  リンクがあり、ページ全体にかけると必ず「許可と制限の混在」で不採用になる
- **箱ごとに判定する**。Commons の多重ライセンス（GFDL ＋ CC BY-SA ＋ CC BY）は普通で、
  箱をまとめると制限側が許可側を潰す。1 つでもホワイトリストに一致する箱があれば、その条件で使う
- 取得するのは原本ではなく**縮小画像**（`/thumb/.../1280px-...`）。原本には 40MB を超えるパノラマがあり、
  ページに載せるには過大で、相手サーバにも負担になる。URL は MediaWiki の決まった配置から組み立てる
- 追跡用の query（`utm_*`）は落とす

### 自治体・観光協会の素材（`assets/terms.py`）
規約ページを既存のホワイトリスト判定にかけ、さらに**「申請」「要相談」「許可を得て」等があれば不採用**にする。
ライセンス名が書いてあっても、利用の可否に人の判断が要るものは自動で回す仕組みに載せられない。

### ビルド時の検査
- ページの `<img>` は、すべて `data-sitemill-asset="<asset_id>"` を持ち、登録済みでなければ**ビルドを止める**
- 登録は任意の Service フック `assets(ws) -> Iterable[Asset]`。`usable`（ライセンス通過、または自作）でない
  資産は登録されない
- サイト自身の図版はインライン SVG にするか、`own_work=True` の資産として登録する

### クレジットの描画
`photo_figure(asset, locale, src)` マクロが、作者・ライセンス・出典ページ・取得日を必ず出す。
ライセンス名は**言語に依らない短い表記**（`CC BY 4.0`）を使い、文の組み立てはロケールのカタログに置く
（ADR 0016）。日本語のライセンス名を英語ページに出さないため。作者が取れない画像は、保存してある
クレジット文にそのまま落ちる。

## 実測（香川 13 施設、2026-09-12）
| 経路 | 結果 |
|---|---|
| Commons | 候補 37 件 → **採用 5 件**（CC BY 4.0 が 4、CC0 が 1）。却下 32 件の内訳は CC BY-SA 28・PD 表示 2・GFDL 混在・画像 URL 不明 1 |
| 自治体・観光協会 | 規約ページを判定できたのは 2 件、いずれも「無断転載禁止」で**採用 0 件** |
| 公式 SNS | 13 施設中 12 施設に公式アカウント（Instagram 11・X 10・YouTube 7）。ただし埋め込み可能な単体動画は 0 |
| Maps | 鍵が未設定のため埋め込み 0、外部リンク 13（想定どおりのフォールバック） |

写真が付いた施設は 13 件中 3 件（23%）。**ホワイトリストが厳しすぎて落ちたものは無い**
（却下の 31/32 はライセンスが明確に読め、ホワイトリスト外だった）。詳細は
japan-open-today の `data/runs/asset-probe.json`。

## 影響
- 第 1 フェーズは写真がほぼ無い前提で成立させる。ADR 0006 の「写真が無くても成立するデザイン」が前提でなく要件になった
- ホワイトリストを広げるか（CC BY-SA の受け入れ、パブリックドメインの扱い）は事業側の判断。
  広げる場合は ADR 0005 に追記する

## 追記（2026-09-14）: 継承（ShareAlike）つきのライセンスを採る

2026-09-12 の追記で、継承つきを「受け入れるとサイトの該当部分に取り消せない義務を負う」と読んで
ホワイトリストから外していた。**この読み方が保守的すぎた**。継承の義務は、その写真と**その改変物**に
及ぶもので、写真を載せたページには及ばない（ページは写真の編集物であって二次的著作物ではない）。

実測でも効いていた。香川の施設で Commons のカテゴリが決まった 58 件のうち 21 件は、先頭 8 枚が
すべて CC BY-SA で、写真が 1 枚も採れなかった。見送った 139 枚のうち 137 枚が継承つきである。

### 採る条件

1. **写真を改変しない**。表示のための縮小はしてよい（Commons のサムネイル URL を使う）。
   切り抜き・色の加工・合成はしない
2. クレジットに**作者名・ライセンス名・出典ページへのリンク**を必ず出す。
   `photo_figure` マクロが 3 つとも出しており、リンク先の Commons のファイルページで
   原文のライセンスが確認できる
3. ライセンス名は言語に依らない短い表記（`CC BY-SA 4.0`）で出す。日本語のライセンス名を
   英語・繁体字のページに出さない（ADR 0016 と同じ）

### 変えたところ

- `LicenseId` に `CC_BY_SA_4_0 / 3_0 / 2_5 / 2_0 / 2_1_JP` を足し、`SHARE_ALIKE` として分けて持つ。
  継承を避けたいサービスは `NO_SHARE_ALIKE` を見ればよい
- `license/detector.py` の拒否規則から `SA` を外した（**非営利 NC と改変禁止 ND は引き続き拒む**）
- 多重ライセンスのファイルは、**義務の少ない箱**を選ぶ（CC BY と CC BY-SA が併記されていれば CC BY）。
  GFDL との併記は、CC BY-SA が選べるならその条件で採る
- 文末の句点でライセンス表記が外れていたのを直した（「CC BY-SA 3.0.」が読めなかった）。
  版番号（3.0.1）は引き続き別物として扱う

判定できない表記は従来どおり不採用。
