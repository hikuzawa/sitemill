# ADR 0021: 地域限定の案件は除外せず保留にする

- ステータス: 採用（2026-09-12）
- 変更元: ADR 0019（案件選定の除外 3「地域が合わない」）

## 背景
ADR 0019 では、成果の出る地域がサイトの対象地域と重ならない案件を除外にした。
クリックされても成果にならないから、という理由だった。

これは掲載面を 1 つ（所有者向けページ）だと見たときの判断で、実際の掲載面はそれだけではない。
akiya-atlas は全国 1,740 市町村のページを持っている。首都圏限定の案件は、所有者向けページでは
成果にならないが、**首都圏の市町村ページでは成果になる**。除外にすると、その案件は構造化データから
消え、地域別の枠を作ったときに同じ検討をやり直すことになる。ADR 0019 が「除外した案件を出力から
消す」を却下したのと同じ理由が、地域の判定そのものにも当てはまっていた。

## 決定
**地域は除外の条件から外し、保留に回す。**

- 点は今までどおりつける。導線・成果条件・確定率・稼ぎの内訳も残す。今の枠に出せないだけで、
  案件としての良し悪しは変わらないため
- 保留にした印を `Screened.region_limited` で持つ。対応エリアの原文は `Candidate.region_quotes`
  に既にあるので、地域別の枠を作るときは**この 2 つで絞り込める**（理由の文字列を読まない）
- 信頼性・導線・しきい値の除外は今までどおり先に効く。地域限定でも確定率が下限を割れば除外になる
- 保留は 2 通りになる（点が届かない／地域が合わない）。同じ表に並べ、根拠の文で区別する

## 影響
- 除外の条件は 1 信頼性・2 導線・3 しきい値の 3 つに詰まる（ADR 0019 の 3 と 4 が 1 つずつ繰り上がる）
- 判定の JSON に `region_limited` が増える。既定は false なので、以前の JSON もそのまま読める
- プロファイルの `region.reason` は「成果が発生しない」ではなく「今の枠には出せない」という
  言い回しにそろえた。除外理由ではなく保留理由として表に出るため
- 地域別の枠そのものは、まだ作らない。作るときに保留の一覧から拾う

## 却下した案
- **地域ごとの掲載枠を先に作る**: 枠の設計（どの市町村ページのどこに出すか、都道府県でまとめるか）は
  掲載面の設計の話で、選定ツールの判定とは別に決める。枠が無いうちは保留で足りる
- **プロファイルから `service_area` を消す**: 地域の情報そのものが判定から消え、どの案件がどこ向けかが
  表から読めなくなる。今は「合うか合わないか」を出し続けることに意味がある
- **地域限定を申請に含める**: 置き場が無いまま提携申請だけ通しても、掲載しなければ失効する ASP がある
